## Problem Statement

The transcription project needs a flawless "Plain-Text Learning Loop" that separates the user's presentation UI (Microsoft Word on OneDrive) from the AI's training data (pure Markdown). Currently, the text extraction script loses manual formatting like bolding (used for canonical Matn text), and the pipeline requires manual copying of files from OneDrive. 

## Solution

Automate the OneDrive retrieval process and preserve all human-edited formatting. A new automation script (`fetch_training_data.py`) will automatically scan specific `(تم التسليم)` (completed) folders in OneDrive, dynamically determine the lecture subject, extract the text while preserving bolding and paragraph breaks via an upgraded `read_docx.py`, save it into `04_Training_Data`, and delete the processed `.docx`.

## User Stories

1. As a transcriber, I want my manual bolding (Matn) in Word to be preserved as Markdown `**` during extraction, so that the AI learns the exact boundaries of the Matn text.
2. As a transcriber, I want my paragraph breaks to be perfectly preserved, so that the AI learns my topic transition structure (like breaking after `طيب`).
3. As a transcriber, I want to simply drop my reviewed `.docx` file into my OneDrive `(تم التسليم)` folder, so that I don't have to manually move files around my local file system.
4. As the automated system, I want to dynamically grab the subject name from the parent folder path, so that the resulting Markdown file is accurately named and categorized.
5. As the automated system, I want to save the extracted `.md` file directly into `04_Training_Data` (e.g., `YYYY-MM-DD_[Subject].md`), so that it's immediately available for the Diff Loop.
6. As the automated system, I want to delete the `.docx` file from the `(تم التسليم)` folder after successful extraction, so that it doesn't get repeatedly processed.
7. As a project maintainer, I want the standard documentation (`CONTEXT.md` and `SKILL.md`) to reflect the new 4-folder architecture (`01_Matn_Sources`, `02_Raw_Inputs`, `03_AI_Outputs`, `04_Training_Data`), so that the AI always has the latest ruleset.

## Implementation Decisions

- **Folder Architecture:** Use standard English folder names (`01_Matn_Sources`, `02_Raw_Inputs`, `03_AI_Outputs`, `04_Training_Data`).
- **`read_docx.py` Modification:** Iterate over `w:r` (runs) within `w:p` (paragraphs) to identify `w:b` or `w:bCs` properties. Wrap text with `**` if bold. Join paragraphs with `\n\n` to preserve empty lines.
- **`fetch_training_data.py`:** Use Python's `glob` to scan `C:\Users\L\OneDrive\1. دوري\*\*(تم التسليم)\*.docx`. Extract the subject by parsing the grandparent directory name. Use `os.remove()` to handle file deletion.
- **Tafreegh SKILL.md Updates:** The Continuous Learning diff loop will trigger from the `(تم التسليم)` directory instead of a local chat drop.

## Testing Decisions

To verify this implementation is correct, we will test at two primary seams:

1. **Unit Seam - `read_docx.py`:**
   - **Test:** Pass a mock `.docx` containing bold runs, non-bold runs, and empty paragraphs.
   - **Assertion:** The output string matches the expected Markdown (bold wrapped in `**`, and paragraph breaks intact).

2. **Integration/Highest Seam - `fetch_training_data.py`:**
   - **Test:** Create a temporary mocked OneDrive directory structure containing a `(تم التسليم)` folder with a sample `.docx`.
   - **Assertion:** After execution, a `.md` file is generated in `04_Training_Data` with the correct naming convention, its content matches the extracted text, and the original `.docx` in the mocked OneDrive folder is deleted.

## Out of Scope

- Processing `.docx` files outside of the `(تم التسليم)` folders.
- Any complex formatting beyond bolding (e.g., italics, colors) are not currently required to be parsed into Markdown.
- Automatic Git commits of the extracted training data.

## Further Notes

The poetry formatting (e.g., using ` ... ` for spaced hemistichs) and paragraph logic (triggering new lines on `طيب`) have been codified into `SKILL.md` so the AI applies them automatically during the transcription phase, reducing the amount of manual formatting needed in Word.
